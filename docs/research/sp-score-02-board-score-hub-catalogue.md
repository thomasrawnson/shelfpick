# SP-SCORE-02 — BoardScoreHub catalogue and reuse audit

Date: 1 November 2026  
Upstream snapshot: [`cophilot/board-score-hub` at `483758f`](https://github.com/cophilot/board-score-hub/tree/483758f2f00b5a0ace2a91555878b65598950d55) (24 October 2026)

## Result

The inspected [`getAllGames()` registry](https://github.com/cophilot/board-score-hub/blob/483758f2f00b5a0ace2a91555878b65598950d55/src/allGames.ts) contains **54 entries**: **53 native score tables** and **one external-only link** (Cascadia). No registered score placeholder or missing definition was found. SETI's rules URL is an empty string, an incomplete metadata field rather than an incomplete score table. The repository also contains no unregistered game folder relevant to this snapshot.

“Native” below means a registered local `View` plus definition, not an independent assertion that every rule is correct. BoardScoreHub has no game-definition test suite, and this audit did not install its dependencies or run its UI. All 53 native models calculate a total and use high-score ordering. BoardScoreHub's play-log formatter selects the first maximum rather than preserving every tied winner, so its winner log must not be copied as the ShelfPick contract.

Compatibility codes:

- **A** — equivalent totals fit SP-SCORE-01 now (numeric category or single-value round inputs, sums, multipliers, variants/expansions, incomplete state and high-score ties).
- **A+** — totals fit now, but faithful convenience UI needs a bounded extension such as fixed-value/exclusive awards, negative-entry controls, alternate layouts, or an end condition.
- **B** — needs repeated multi-category rounds; not representable cleanly by the current single-value `rounds` mode.
- **N/A** — no native model to assess.

Their transitive dependencies and notices would still require an SBOM/licence scan if any upstream implementation were reused. ShelfPick needs none of these packages merely to implement data templates.

Scoring mechanics and totals should be independently verified against an authorised publisher rulebook or owner-supplied copy. Do not copy descriptive prose. BoardScoreHub is useful corroborating implementation evidence, not a canonical rules or rights source.

## Audit limitations

- BGG IDs are parsed from each native definition's BGG URL; Cascadia's 295947 is identifiable but absent from its external registry object.
- Source structure, counts, URLs, categories and calculation hooks were inspected at the pinned commit. The upstream UI was not built, and no runtime claim is made.
- “A” means the mathematical result can be represented, not that the template is rule-approved, visually approved, accessible, offline-ready or owner-approved.
- Azul is **not registered** in this snapshot. It needs a separate primary-rule investigation and cannot be presented as BoardScoreHub reuse evidence.
