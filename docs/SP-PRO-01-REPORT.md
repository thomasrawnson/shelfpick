## Outcome

Users can buy Pro Lifetime or Pro Yearly in the iOS app, restore it, and manage
a yearly subscription. The server grants Pro only from RevenueCat's own record
of the account's purchase. Expiry or refund returns the account to Free; manual
and test Pro grants are untouched.

## Design

- **Identity.** New `users.public_id` (random UUID, database default, unique) is
  the RevenueCat app user ID. No email or numeric ID leaves the server.
- **Server trust.** `POST /billing/sync` (signed-in) and
  `POST /billing/revenuecat/webhook` (shared-secret header) carry no purchase
  data that is believed. Both call RevenueCat's subscriber API with the server
  secret key and store the result in `purchase_entitlements` (plan, product,
  status, expiry, store, sandbox or production). A failed lookup grants and
  removes nothing (502; RevenueCat retries webhooks).
- **Tier.** `resolve_tier` returns PRO for `users.tier = PRO` (manual or test
  grant) or an unexpired active purchase, so a lapsed yearly plan stops
  unlocking Pro at its expiry time even if a notification is late. Every
  existing capability check goes through `resolve_tier`, so nothing else changed.
- **Lapse.** Custom scoresheets, rankings and plays stay readable; the Pro tools
  lock (covered by a test that creates a custom sheet, lapses and reads it).
- **Paywall.** One screen at Settings > Pro (every locked preview and Settings
  already link there): Pro Yearly and Pro Lifetime with store prices and
  periods, equal weight, auto-renew terms, Privacy and Terms links, Restore
  purchases and Manage subscription, plus the Free/Pro comparison with the new
  features. Buying is iOS-only; the PWA says so. **Purchases stay closed until
  `VITE_PUBLIC_LEGAL_LINKS_ENABLED=true`** so a price is never shown without the
  legal links beside it (the project's existing fail-closed rule).
- **Flow.** The app finishes the App Store sheet through
  `@revenuecat/purchases-capacitor` 14.1.1 (Capacitor 8, SPM), then asks the
  server to confirm, checking up to four times, 2.5 s apart (the server allows
  one RevenueCat lookup per user every 2 s), for RevenueCat to catch up.
  Pro shows only after the server confirms it. Loading plans times out after
  60 s with Try again (was 15 s; that hid the cause of a TestFlight failure),
  and the message now ends with the SDK's error code and text.

## Not done

- **No sandbox purchase through the App Store.** It needs the RevenueCat
  project, its keys, the `default` offering and an App Store sandbox tester,
  none of which exist in this repository. Acceptance criterion 5's sandbox
  purchase is therefore **not met**; the server logic is tested against a fake
  of RevenueCat's documented subscriber response, so the first real sandbox
  run may still reveal a field-name or timing difference.
- No VoiceOver walkthrough (owner), and no physical-device check.
- The Free/Pro comparison page is one screen with the paywall at the top
  rather than a separate paywall route; every entry point already led there.

## Risks

- **Sandbox purchases grant real Pro in production.** App Review buys in the
  sandbox against the production server, so the server accepts them and records
  `environment = SANDBOX`.
- **Privacy.** RevenueCat is a new processor receiving the random account ID and
  purchase data. The hosted privacy policy, App Store Connect "Purchase
  History" answer and the processor record are owner tasks before release.
- **Shared Apple Account.** RevenueCat moves a purchase to the newest account
  that restores it; the previous ShelfPick account is downgraded by webhook.
- **Locked previews.** Free sees no custom-scoresheet builder or preview
  (unchanged from SP-SCORE-01), yet the paywall lists custom scoresheets as a
  Pro benefit. Whether to add a locked preview is a separate decision.
- **Tips.** The tip jar is still hidden in release builds; this task sells Pro
  only.
- A webhook and a `/billing/sync` for the same user arriving in the same instant could both try to create the purchase row; the unique constraint rejects one with a 500 and the next RevenueCat retry or sync succeeds. Not handled specially.
- The webhook route is public by design and protected only by the shared
  secret; use a long random value.

## Rollback

Remove the two RevenueCat secrets (billing turns off, existing purchase rows
keep working until expiry) or redeploy the previous commit. Do not downgrade
the migration while purchase rows exist. Deploy order: API with the migration,
secrets and webhook, then the app build.

## Follow-up: erasing the RevenueCat customer on account deletion (18 November 2026)

Deleting a ShelfPick account now also asks RevenueCat to erase the customer, using the random account ID, after the database deletion has committed. A failure never undoes the deletion; it is logged as a warning with the random ID so the record can be erased by hand. It uses the existing RevenueCat version 1 secret key, which has no permission setting; a sandbox account deletion should be checked against the RevenueCat dashboard (see the runbook). An earlier version of this note wrongly said the key needed read and write access. Backend: 656 passed, 17 skipped on a disposable PostgreSQL database; `alembic check` clean. Not deployed.

## Follow-up: paywall never loaded plans on TestFlight (19 November 2026)

Cause: `loadRevenueCat` returned the Capacitor plugin object from an async function. A Capacitor plugin answers to every property name, including `then`, so JavaScript treated it as a promise and waited for a native `then` that does not exist. The promise never settled, so the paywall waited until its timeout (15 s, then 60 s) with no error. It was found by running a debug build on a physical iPhone with the console attached, where the log stopped after the first plugin call.

Fix: `sdkFromPlugin` hands the store a plain object of calls (`frontend/src/billing/store.ts`), with a test that uses a plugin-like proxy. `npm test` 254 passed, lint and `tsc -b` clean.

Device evidence (physical iPhone 15 Pro Max, debug build 1.2 (99) run from Xcode, **not a TestFlight build**): Yearly and Lifetime plans loaded, a sandbox purchase completed, and the app showed Pro active. Restore, expiry, refund and account-deletion erasure are still untested. No TestFlight build contains this fix yet.
