# SP-IOS-07A — Dynamic Type and accessible text reflow

4 November 2026. Isolated `codex/sp-ios-01` worktree. The dirty primary checkout, Personal Team prototype, company signing resources and deployed backend configuration were preserved. No commit, push, merge, deployment or distribution occurred.

## Implementation

WebKit's [`-apple-system-body` style](https://webkit.org/blog/3709/using-the-system-font-in-web-content/) supplies the iOS preferred text size to the Capacitor WebView. The native-only stylesheet converts ShelfPick's four core typography tokens to rem values with the same approximate Large-size pixels (16/14/12/11), and converts the most visible fixed-size headings, choices, card titles, buttons and bottom-nav labels. Its reflow rules let auth content, game titles, choices and navigation wrap or scroll. The browser/PWA tokens and viewport remain unchanged; pinch zoom is not disabled. WebKit's [WKWebView Larger Text issue](https://bugs.webkit.org/show_bug.cgi?id=187013) explains why ordinary CSS pixel sizes did not respond. Apple's [Dynamic Type guidance](https://developer.apple.com/videos/play/wwdc2024/10074/) distinguishes standard and accessibility sizes and calls for reflow.

The Keychain adapter now keeps a nonsecret marker in the app's WebView container. On a genuinely fresh installation, before credential restoration or save, it enumerates Keychain keys and removes only ShelfPick's known account token and Game Night guest keys, then writes the marker. Ordinary updates retain it. A one-time staged marker-seeding build kept the owner's existing company-app session through this update; that seed script is absent from the final build. Any other pre-marker installation would require one fresh login.

### Physical iPhone 15 Pro Max, iOS 27.0.1

The owner set standard **Large**, then named **Accessibility Medium** and **Accessibility Extra Extra Large**. Device Hub used the same 1100×800 fit setting for comparisons. At Large, Picker's “What should we play?” heading occupied 15 bright raster rows (y=170–184); at Accessibility Extra Extra Large, its first word “What” occupied 50 rows (y=169–218), a **50/15 ≈ 3.3× visual glyph-height ratio**. This was measured in the x=400–639 screen region, counting rows with at least seven pixels whose RGB channels all exceeded 185; it is a screenshot ratio, not a CSS computed font size. At Accessibility Medium the same heading visibly enlarged and wrapped to two lines, with the Picker choices, Continue action, Collection, Settings, Profile and deletion form reachable by scrolling. No numeric Medium ratio was retained.

The first Extra Extra Large inspection exposed concrete clipping: Collection's title broke into two-letter fragments beside Add game, Picker complexity names overlapped, Profile avatar labels ended in ellipses, and Collection filter names clipped. Native-only auto-fit grid and wrapping corrections were then built, company signed with the existing identity/profile, installed and visually retested on the physical iPhone. The final build stacks Collection's heading and Add game; Picker complexity choices form two columns and Continue is reachable; Collection section/filter tabs form two columns and search/sort stack; Profile avatar choices form two columns with untruncated labels. The Delete account password, acknowledgement and final control were visible by scrolling; **Delete was not activated**. The existing signed-in session survived both local app updates. The fixed bottom navigation remains horizontally scrollable: a physical Device Hub swipe revealed the initially hidden Insights tab at Accessibility Medium, while Extra Extra Large shows only about two tabs at a time. This is a discoverability and VoiceOver follow-up risk, not a claim that all tabs fit simultaneously. Long words such as “Medium” and “Unplayed” can break mid-word at the largest tested size, but their text remained visible. No page-width overflow was evident in the observed screens; computed WebView width was not captured.

The final iPhone 17 simulator build compiled, installed and opened the login form at standard Large. Physical VoiceOver speech/focus, unplugged software keyboard and pinch/pan on the final Extra Extra Large build are pending owner feedback. The physical login/verification form and a live reinstall were not tested at these named sizes.
