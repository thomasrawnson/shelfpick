In Device Hub, iPhone 17 simulator (iOS 27.2) rotated to landscape and Picker remained operable by scrolling, though the short viewport put controls near the fixed bottom navigation. No orientation policy was changed. **Recommendation for owner decision:** ship iPhone portrait first unless landscape and iPad layouts receive dedicated testing; if landscape remains supported, address its cramped Picker layout before submission. Do not change orientation support without owner approval.

The simulator was changed from `large` to `accessibility-extra-extra-large`, the app was viewed and cold-launched, and text in Picker did not visibly enlarge. The simulator category was restored to `large`. WebView typography therefore does not yet demonstrate Dynamic Type support; Settings, Collection and Picker need an actual larger-text usability pass. The existing physical VoiceOver pass remains valid, but it is separate from larger-text evidence.

Capacitor 8.6 defaults iOS `zoomEnabled` to `false`, despite ShelfPick's viewport meta omitting any user-scale restriction ([Capacitor config](https://capacitorjs.com/docs/config)). This prevented normal native WebView pinch zoom. The only code change here adds `ios.zoomEnabled: true` to `frontend/capacitor.config.ts`; the synced native config contains `"zoomEnabled": true`. The rebuilt app opened on iPhone 17 with Picker and bottom navigation visible at normal scale. Device Hub has no multi-touch pinch control, so an **actual 200% pinch and pan check remains unverified**; do not infer it from the config alone. Safari/PWA viewport settings were not changed.

## Authentication and return links

`frontend/src/auth.ts` stores the bearer JWT in WebView `localStorage`; `App.tsx` removes it on ordinary logout and returns to login. Physical cold-launch persistence and logout were verified in SP-IOS-02B, but ordinary logout does not revoke the token server-side; the separate “Log out all devices” path calls `/auth/logout-all`. Guest Game Night credentials also use localStorage. There is no Keychain-backed native storage. Apple review rules do not expressly require Keychain for this token, so this is a **security and release decision**, not an automatic guideline rejection. Minimal implementation: an iOS-only Keychain storage adapter, web localStorage unchanged, asynchronous session bootstrap, a controlled migration or forced re-login, and restart/logout/expiry/account-deletion tests. Do not use unencrypted Preferences for the JWT or log credentials.

Verification and reset emails currently use `FRONTEND_URL` plus `/verify-email?token=…` and `/reset-password?token=…`; Game Night share links use `/game-night/join/{token}`. The native app has no Associated Domains entitlement, AASA file or `appUrlOpen` routing handler, so these HTTPS URLs currently remain web flows. A bounded Universal Links milestone needs the final Team ID + bundle ID, the exact approved frontend host, an AASA file at `/.well-known/apple-app-site-association`, an `applinks:` entitlement, and a Capacitor App URL listener for allowlisted paths and both cold/warm launches ([Apple associated domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains), [Capacitor deep links](https://capacitorjs.com/docs/guides/deep-links)). Token-bearing links must be validated and kept out of logs. Hosting and any backend `FRONTEND_URL` adjustment require separate authorization; web fallback must continue to work.
