## Physical accessibility evidence

The owner set the company-signed iPhone 15 Pro Max (iOS 27.0.1) to the standard **Large** text size and opened Picker. Device Hub showed the heading, player and complexity choices, Continue action and bottom navigation fully visible in portrait, with no evident horizontal clipping. This is the baseline visual observation; the phone's named setting was owner-reported, and no font pixel ratio was measured.

I then used Device Hub to move iOS Settings → Accessibility → Larger Text to the **maximum accessibility slider position**. System Settings text expanded dramatically and wrapped over several lines; the same ShelfPick Picker heading, option labels and bottom navigation showed **no discernible size change** from baseline. Collection and Settings/Profile text also looked small. Picker Continue, Collection search and bottom navigation remained visible, and the Profile deletion form was reachable by scrolling without activating its final control. This physical visual comparison does not demonstrate WebView text scaling. It differs from the owner's broader SP-IOS-06 impression that Picker labels grew; neither observation includes a measured font pixel ratio. The exact named UIKit category was not exposed in Device Hub, so maximum position is recorded rather than an invented category name. Device Hub showed a keyboard accessory toolbar when Collection search focused, but not the software keyboard; that observation alone is not a software-keyboard pass.

The owner reported setting standard **Extra Extra Large** and opening Picker, but Device Hub did not capture that category before I changed the slider, so no comparative text measurement is claimed for it. At a later large accessibility position the owner reported that actual VoiceOver focus, labels and activation worked across Picker, Collection, Settings → Profile → Delete account and bottom navigation. With the iPhone disconnected from the Mac, the owner reported that Collection's software keyboard appeared and dismissed with controls reachable. A two-finger pinch initially failed while VoiceOver was on; after turning VoiceOver off, the owner confirmed that ShelfPick **zoomed and panned**. This is a gesture-mode difference, not evidence of a WebView pinch regression. Exact spoken phrases, two named accessibility categories, login at enlarged text, and a measured font ratio remain unverified. The iPhone 17 simulator's SP-IOS-06 `accessibility-extra-extra-large` check also showed no clear text growth; the previously tried WebKit system-font CSS was discarded because its large login layout clipped controls. The smallest practical fix is an iOS-only Dynamic Type typography token tied to WebKit's system text style, then bounded reflow of Picker choices, Collection rows, Settings/Profile, login and bottom navigation at each named category. A blanket page scale or viewport cap would not preserve usability or zoom.

Device Hub slider drags did not reliably land on the prior physical text position. The owner subsequently confirmed restoring their preferred iPhone text size. Device Hub then showed the phone on its Home Screen; the exact restored category was not independently read.

## Native session evidence

The new synthetic Capacitor iOS bridge test exercises the actual Keychain plugin path with fixture strings only. It verifies native token save, in-memory use, asynchronous restore, localStorage removal, `whenUnlockedThisDeviceOnly` and non-synchronizing storage, logout/expiry cleanup, guest credential restoration/removal, and post-success account-deletion cleanup. A mocked failed deletion leaves the session intact. It does **not** claim a live Game Night vote, server JWT expiry on the phone or actual account deletion. Existing backend tests, run with disposable in-memory SQLite, passed for expired JWT rejection, logout-all revocation and password-reset revocation (3 passed). Live logout-all was deliberately avoided to preserve the owner's sessions. SP-IOS-06 physical force-quit restoration and ordinary logout remain prior evidence, not repeated here.

Keychain items may persist across uninstall and reinstall of the same bundle ID. The current adapter has no first-install marker, so a still-valid account JWT or guest credential could restore after reinstall. Before distribution, add an app-container first-install marker: on an absent marker, clear only ShelfPick's known native credential keys and require login, then write the marker. Verify update preserves a session while uninstall/reinstall requires login. This is a session-privacy risk, not a demonstrated App Review rule violation.
