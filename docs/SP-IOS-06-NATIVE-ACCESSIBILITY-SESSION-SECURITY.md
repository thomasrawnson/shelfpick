## Accessibility evidence and decision

On the company-signed iPhone 15 Pro Max (iOS 27.0.1), the owner physically pinched the ShelfPick page to approximately 200%, panned, reached Picker and bottom navigation, and pinched back. The owner also changed **Accessibility → Larger Text** to an accessibility size and reported that Picker labels visibly enlarged. Device Hub showed login, Picker, Settings and the bottom navigation visible during the larger-text period. The owner reached and used Settings → Log out; login remained after restart. On the **final** installed company build, the owner enabled actual VoiceOver, signed in, moved through Picker, Collection, Settings and bottom navigation, and reported that labels, swipe order, double-tap actions and Larger Text reachability worked. These are human/physical observations, not an automated measurement of the exact font-size ratio. All Picker substeps and the maximum named accessibility text category were not systematically measured.

The iPhone 17 simulator (iOS 27.2) still showed no clear login-text change after `simctl ui ... content_size accessibility-extra-extra-large` and a cold launch. An iOS-only CSS experiment using WebKit's documented `font: -apple-system-body` did cause dramatic text growth in that simulator, but its very large login text required scrolling and initially clipped controls. A reflow experiment made the login submit action reachable, but signed-in Collection, Picker and Settings at that scale remained unverified. **Both CSS experiments were discarded**; the final physical build retains the previously working typography and `ios.zoomEnabled = true`. The simulator category was returned to `large`, and the verified Keychain build was restored there. The discrepancy between physical observation and simulator rendering is a release risk; no blanket scale cap or pinch restriction was added. [WebKit describes system text styles and Dynamic Type](https://webkit.org/blog/3709/using-the-system-font-in-web-content/).

## Secure iOS sessions

`@aparajita/capacitor-secure-storage@8.0.1` supplies iOS Keychain storage under Capacitor 8.6. The adapter uses local, non-synchronizing Keychain operations with `whenUnlockedThisDeviceOnly` access for both account JWTs and Game Night guest credentials. The account token is cached **in memory only** for synchronous API Authorization headers. Startup awaits native Keychain restoration before `/auth/me`; login awaits Keychain persistence before opening the app. Logout, 401 expiry and successful account deletion clear the native key. Game Night guest restoration also awaits Keychain read, and an invalid guest credential is removed. Web/PWA continues to use its existing `localStorage` path and does not call the plugin's unencrypted web implementation.

The first company build with this adapter deliberately removed an old company-ID WebView JWT and displayed login, requiring the owner to sign in again; no token was transferred from either bundle ID. The owner signed in on the physical iPhone, force quit and reopened the app, and reported an authenticated screen. The owner then used ordinary Settings logout, force quit and reopened, and reported that login remained. The final company build was installed and launched afterward; Device Hub first showed its login form, then showed the signed-in Picker after the owner's VoiceOver sign-in. An update of the same signed build preserved that Keychain session and reopened Picker. No credentials, JWT values or personal records were collected or logged.

The backend `/auth/logout-all` contract was unchanged. Existing backend tests for logout-all revocation, expired access tokens and password-reset revocation passed against a disposable in-memory SQLite configuration (3 tests). A live logout-all action was not performed because it would revoke the owner's other active sessions. Completed account deletion was not tested because deleting the owner's account is excluded; only its post-success cleanup path was changed. Guest Game Night Keychain restoration was not exercised with a live voting session.

## Remaining release gates

The physical Larger Text observation should be repeated at named categories with measured reflow and keyboard checks; the owner reported a successful VoiceOver pass on the final company build, but exact spoken phrases and a recorded focus trace were not captured. Native session expiry, live logout-all and Game Night guest restoration are not physically verified.
